Track C — the framework

LlamaParse turns any document into markdown; then you extract against the same schema. You are here to find out what a framework buys you, and what it charges.

Read this before you start This track has never been executed. Track A was run end to end many times and every number quoted for it is measured. This one was corrected from the provider documentation during the pre-flight, but we had no API key, so no call has ever completed. Expect to be the first person to run it. Start at --limit 1, and read the error on the first row rather than the wall of them.
Why

The two-stage pattern

This is the shape most real document pipelines end up in, and it is worth seeing even if you would not choose it today.

The idea

Parse first, extract second

PDF ──► LlamaParse ──► markdown
                          │
                          ▼
              extract against Invoice

Stage 1 turns any document into clean markdown — a scan, a rotated table, a 40-page contract. Stage 2 is plain text extraction against the same schema.Invoice every other track uses. The framework buys you stage 1. It is genuinely the part you would not want to build.

Now the honest half — say this at demo time For today's documents this is arguably overkill. Our PDFs are born-digital, so the text layer is already perfect and pdfplumber reads it for free — that is gotcha G4, and Track A proves it at 8 s/doc for ₹0. Stage 1 earns its keep on documents you cannot read for free.

The price is three unpinned packages, no version floors, and a model lookup that happens inside the framework before a single request is sent. You pay the framework tax before you extract one field. Open your cost column when you say it.
Before

Install — at home, not at the venue

Step C1

Uncomment the dependencies and install them

The llama-index lines in requirements.txt are commented out on purpose — the install is heavy and it is not fair to make forty people download it over venue wifi.

# requirements.txt — remove the leading '#' from these three
llama-cloud-services
llama-index-core
llama-index-llms-anthropic

pip install -r requirements.txt
Check it worked 
python -c "import llama_cloud_services, llama_index.core; print('ok')"
Step C2

Two keys, not one

echo 'LLAMA_CLOUD_API_KEY=llx-...'   >> .env   # stage 1, LlamaParse
echo 'ANTHROPIC_API_KEY=sk-ant-...'  >> .env   # stage 2, extraction

Free LlamaParse tier at cloud.llamaindex.ai covers today. Stage 2 costs the same as Track B, because it is the same model.

Step C3

One document, and expect to debug the install before the API

cd 03-parser
python track_c_llamaindex.py --dataset ../02-generator/dataset --limit 1
Three things fail before the network does — in this order 1 · ModuleNotFoundError: llama_cloud_services — Step C1 not done. This is failure number one for everybody.
2 · It raises inside Anthropic(...) before any request is sent. llama-index ships its own model → context-window registry and looks the id up on construction. A release older than the model you name raises right there. Fix: upgrade llama-index-llms-anthropic, or name one it knows: python track_c_llamaindex.py --model <an id your version knows> --limit 1
3 · Credentials. Both keys, repo-root .env. Missing LLAMA_CLOUD_API_KEY fails in stage 1, before extraction is ever attempted.
Check it worked [C-llamaindex] inv_0001 OK …s, then done: 1 ok, 0 errors. Stage 1 is a network round-trip per document, so expect this to be slower than Track B.
Step C4

Then five, then the hundred

python track_c_llamaindex.py --dataset ../02-generator/dataset --limit 5
python track_c_llamaindex.py --dataset ../02-generator/dataset
Watch the page count, not just the clock LlamaParse bills by page and the free tier is finite. 100 one-page invoices is 100 pages. Check your remaining quota before you run the batch, not after.
