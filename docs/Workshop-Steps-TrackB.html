The idea

Make the model answer through your schema

tool_choice={"type": "tool", "name": "record_invoice"}

Without this you get prose with JSON buried in it — markdown fences, an apology, a trailing comma — and you write a fence-stripper that breaks on the document that matters. common.coerce_json in this repo is exactly those twenty minutes, pre-spent.

With a forced tool choice the model has no prose option. It must call record_invoice, and its arguments are your fields. The pattern outlives the vendor — OpenAI's equivalent is response_format with json_schema + strict.

Be precise about what it buys — this is the exam question A forced tool call guarantees you receive a tool_use block. It does not guarantee that block validates against your schema. The parameter that guarantees validation is strict: true, and strict requires additionalProperties: false plus required — neither of which Pydantic's model_json_schema() emits. So today the shape is guaranteed by construction, and correctness is still caught by Invoice.model_validate() in common.py.

Structured output removes a class of parsing bugs. It does not remove your validation layer. Anyone who tells you otherwise has not read the docs.

What it costs — estimated, not measured

The number

₹0.75 a document, and why we cannot prove it

At Sonnet 5's published $2 / $10 per million tokens, one of our one-page invoices is roughly 2,500 input + 350 output tokens:

input   2,500 × $2/1M  = $0.0050
output    350 × $10/1M = $0.0035
                       ≈ $0.0085/doc  ≈ ₹0.75/doc
ScaleCostWhat that is
today's 100 documents≈ ₹75less than the chai order
1M documents / month≈ ₹7.5 lakha headcount
This is an estimate, and that is the lesson track_b_api.py never reads resp.usage, so this repo cannot tell you what a document actually cost — on the one track that could measure it. That is gotcha G6 ("cost measured but never extrapolated") happening in our own code. Want the real figure? Read usage.input_tokens / usage.output_tokens off the response, write them into each JSONL row, and sum. About six lines. It is the best twenty minutes you could spend on this track.
